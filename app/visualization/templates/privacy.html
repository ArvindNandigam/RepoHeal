RepoHeal Privacy Policy

Effective date: June 15, 2026. This policy explains what data RepoHeal collects, why it is collected, where it is stored, and how it is handled.

01 Introduction

RepoHeal is a developer intelligence platform and GitHub App that analyzes codebases to provide health reports, migration intelligence, dependency graphs, and continuous monitoring. We prioritize privacy, security, and data minimization at every step of our analysis pipeline.

02 Information Collected

RepoHeal collects and processes only the information strictly necessary to provide repository analysis and migration guidance:

  • GitHub account identifiers: Username, avatar URL, and GitHub user ID for authentication and repository authorization.
  • Repository metadata: Repository name, description, visibility (public or private), default branch, file listings, and commit SHAs.
  • Dependency manifests: Declared dependencies from package configuration files (such as requirements.txt, pyproject.toml) and detected AST import statements.
  • Analysis artifacts: Syntax trees, dependency graph snapshots, API fingerprints, health scores, risk assessments, and migration findings derived from repository contents.
  • Monitoring records: Health score timelines, alert configurations, watched dependencies, and notification preferences.
  • Operational logs: Request timestamps, job transitions, and error events without sensitive tokens or source code payloads.

Strict Promise: RepoHeal does not sell, lease, or monetize user data. Data is processed solely to provide repository health analysis and migration assistance.

03 Repository Content & Security

Source code is scanned for dependency imports, API signatures, and version compatibility:

  • Source files are processed in-memory whenever possible. Disk cache is automatically governed by quota policies and cleaned up after job execution.
  • Only derived analysis metadata (graphs, fingerprints, health reports) is stored in the repoheal.meta branch or operational database. Raw repository source files are never permanently mirrored.
  • Source code is never used to train publicly available machine learning models.

04 Third-Party Services

RepoHeal utilizes selected infrastructure providers with minimal necessary data scope:

  • GitHub: Repository content retrieval, OAuth session verification, webhook processing, and authorized pull requests.
  • MongoDB Atlas: Operational state, analysis jobs, monitoring alerts, and encrypted session data.
  • Neo4j AuraDB: Semantic knowledge graph storage, dependency topology, and relationship indices.
  • Groq / LLM Providers: Migration intelligence and patch generation. Library names, function signatures, and targeted snippets are passed only as needed.
  • Serper / Search APIs: Public documentation and migration notes lookup for deprecated APIs.
  • PyPI: Package version availability and release metadata.

05 Security Architecture

RepoHeal implements enterprise-grade technical safeguards:

  • End-to-end TLS/HTTPS encryption for all web and API traffic.
  • Fernet symmetric encryption for session tokens at rest using environment-managed keys.
  • HMAC-SHA256 signature verification on all incoming GitHub webhook deliveries.
  • Strict adherence to least-privilege GitHub App permissions—no administrative or deletion rights are requested.

06 Data Retention & Deletion

Data retention follows automated expiration limits:

  • Analysis snapshots are capped at 2 historical versions per repository.
  • Temporary repository file caches expire within 7 days.
  • Session tokens expire after 24 hours and are cleaned up on cycle.
  • Evidence cache records maintain a 30-day time-to-live.

Upon uninstalling the RepoHeal GitHub App, repository analysis records can be permanently deleted upon request by contacting our team.

07 User Rights & Controls

You maintain full control over your repositories and data:

  • Revoke Access: Uninstall RepoHeal anytime via GitHub App installation settings.
  • Inspect Findings: Review all generated graphs, scores, and reports directly in your workspace.
  • Data Erasure: Request complete removal of all stored telemetry and analysis results.
  • On-Demand Refresh: Triggering a reanalysis replaces prior cached snapshots with fresh data.
